# Notes App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A free offline Windows desktop app ("Notes") with rich-text notes, to-dos and a weekly class calendar, launched from a Desktop shortcut, storing everything in `C:\Note\data`.

**Architecture:** Electron app built with electron-vite. `src/main` owns the window and all disk access (atomic JSON files in the data dir); `src/preload` exposes a typed `window.api`; `src/renderer` is a React UI using zustand stores that persist through a debounced saver. Pure logic (time math, calendar layout, task grouping, note filtering, data normalization) lives in `src/shared` and is unit-tested.

**Tech Stack:** Electron, electron-vite, Vite, React, TypeScript (strict), TipTap 3, zustand, date-fns, lucide-react, Vitest, Playwright (`_electron`), electron-builder.

**Spec:** `docs/superpowers/specs/2026-10-29-notes-app-design.md`

## Global Constraints

- Platform: Windows 11, Node 24; use the latest Electron/electron-vite/Vite that install together.
- TypeScript `strict: true` everywhere. Renderer never imports Node modules — only `window.api`.
- Data dir order: `NOTES_DATA_DIR` env → packaged `<exe dir>\..\..\data` → dev `<project root>\data`.
- Times = minutes since midnight (number). Weekday = JS convention 0=Sun..6=Sat. Dates = `YYYY-MM-DD` in **local** time (never `toISOString()` for dates).
- Writes are atomic (`.tmp` + rename, retry on EPERM/EBUSY). Unparseable files are renamed `.corrupt-<timestamp>`, never overwritten.
- Renderer save debounce: 400 ms. Close-flush timeout: 3000 ms.
- Calendar: default hours 07:00–22:00 (`dayStart: 420`, `dayEnd: 1320`), week starts Monday (`weekStartsOn: 1`), 24h time, 5-minute snap, 15-minute minimum duration.
- Backups: `data/backups/YYYY-MM-DD`, keep newest 7.
- Product name "Notes"; packaged exe at `release/win-unpacked/Notes.exe`.
- Security: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, CSP meta tag, external links → `shell.openExternal` (http/https only), single-instance lock.
- Every task ends with `npm test` and `npm run typecheck` passing, CLAUDE.md progress updated, and a git commit.

## Review Focus

1. User types, then closes the window within 400 ms → the last keystrokes are on disk after relaunch (Task 3 saver flush + Task 13 e2e test).
2. A hand-edited or corrupted JSON file (`tasks.json` = `{oops`, a broken note file) → app still opens, other data loads, bad file kept as `.corrupt-*` (Task 2 tests).
3. Times around local midnight in UTC+8 (user's likely zone) → `toISODate(new Date(2026, 9, 29, 0, 30))` is `2026-10-29`, week days don't shift (Task 2 time tests).
4. A class scheduled outside the visible hours (06:00 when grid starts 07:00) → grid expands to show it rather than hiding it (Task 8 `visibleRange` test).
5. Dragging/resizing a block past the top/bottom of the day, or entering end ≤ start → result clamped to 00:00–24:00, end ≥ start + 15 (Task 9 `applyDrag` / `validateSlot` tests).
