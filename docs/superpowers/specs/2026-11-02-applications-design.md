# Applications: profile, tracker, file storage, CV-ready data (v1.4)

Approved in chat 2026-11-02 (plan + "ok"). Tasks 28–34 are in `plans/2026-11-02-applications.md`.

## Goal

Store the user's "about me" data once, track each scholarship/job application, keep proof documents in an
in-app file area, and keep the data clean enough to generate a CV and portfolio later.

## Decisions

- **Navigation:** one sidebar item **Applications** (`Page = 'applications'`) with a segmented control for the
  tabs *Applications · Profile · Files*. No router exists, so a tab is local component state.
- **Persistence (same as the rest of the app):** JSON files in the data folder, atomic writes, `normalize*`
  on every read and write, debounced `saver` from the UI.
  - `profile.json`, `applications.json`, `files.json` (folders + file metadata) and the file bytes in `files/<id>.<ext>`.
  - The daily backup copies all of it already (no change).
- **Schema** lives in `src/shared/profile.ts`, `applications.ts`, `files.ts`; no UI imports. Bilingual text is
  `Bi = { mn, en }`. Dates are partial ISO strings (`2019`, `2026-06`, `2026-06-12`), `'present'` or `''`.
  Every profile entry has `id`, `includeInCv`, `fileIds`; entries with long text also have `summary` (short, for a CV)
  and `description` (long, for applications).
- **Single source of truth for links:** the *referencing* side holds `fileIds` (profile entries and applications).
  "What does this file prove?" is derived (`linksForFile`). Deleting a file removes the references.
  Likewise `AnswerBankItem.usedIn` is derived from applications (`answerUsedIn`); `characterCount` is recomputed on save.
- **Deadline on the calendar:** the calendar already draws tasks with a due date. An application with a deadline gets a
  linked `Task` (`Task.source = { applicationId, stepId: null }`). Steps marked "Add to to-dos" get a task with
  `stepId` set. Two pure functions keep them in sync (`reconcileTasks`: applications → tasks, `syncStepsFromTasks`:
  tasks → steps); a subscription set up in `main.tsx` calls them when either store changes. They return the same
  array when nothing changed, so there is no update loop. Deleting a to-do un-links the step; deleting an application
  removes its tasks.
- **Seed:** when `profile.json` does not exist, main writes the starting data once. The `seeded` flag lives in the
  profile, so deleting entries never brings it back. The starting data is `data/seed.json` (an export file, git-ignored,
  so personal details stay out of the repo) or, without it, a generic seed: an empty profile and the usual folders.
  Tests, e2e and screenshots use the made-up `tests/fixtures/seed.json`.
- **Files:** stored on disk; per-file cap **100 MB** (bytes pass through IPC in memory); otherwise disk space is the limit.
  Folders: one level of nesting. Preview through the `attachment://stored/<name>` protocol (images and PDFs).
  Drag-out uses `webContents.startDrag` from main (copy to temp under the original name), because the Chrome
  `DownloadURL` trick is not reliable in Electron. Fallbacks: Download (save dialog), Reveal in Explorer, Copy file path.
- **Copy buttons** use Electron's `clipboard` through `window.api.app.copyText` (reliable on `file://` pages).
- **Export / import:** one JSON bundle `{ format, version, profile, applications, files (index), jsonResume }`
  plus an "Export everything" folder that also copies the file bytes into `files/`. Import reads the JSON,
  normalizes, replaces the three data sets (after an automatic backup of the current ones) and copies any
  `files/` beside the JSON. `jsonResume` is generated by `src/shared/jsonResume.ts` (basics, work, volunteer,
  education, awards, skills, languages, projects); only entries with `includeInCv` are mapped. Import ignores
  `jsonResume` (the app's own fields are the source).
- **Not built now:** the CV and portfolio generators, a zip export, drag a file into another site's upload box.

## Testing

Unit tests for normalizers, text counting, application logic, task reconcile/sync, file links, seed, JSON Resume
mapper, export/import round trip, stored-file path safety. E2E: create an application, move status, tick steps,
see the deadline on the calendar. Screenshots with `scripts/screenshot.mjs`.
